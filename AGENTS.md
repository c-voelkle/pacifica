# Pacifica — instructions for AI collaborators

## Session start and end

Run `python3 tools/session.py start` (add `--topic <word>` for the subject at hand) before reading or editing canon, and `python3 tools/session.py end` before finishing. Start confirms the branch is current, lists unmerged branches, runs the canon checks and shows where the last session stopped. End lists what would be left behind: canon changed without a CR, facts or synchronization; failing checks; uncommitted or unpushed work; a missing "Resume here". Both only report; resolve or report each item to the author before ending.

## Fresh-context review

After a substantial draft or before adoption, run one review in a fresh context: give the reviewer only the candidate text, the affected canon passages and this file, never the writer's notes or reasoning. Do give the reviewer the draft's `## Canon tensions` section: departures listed there are proposals for the author, to be judged on their merits, not regressions to correct. One pass covers consistency (dates, identities, authority, knowledge, protected mysteries) and literary effect (agency, motive, conflict, viewpoint). Run `lint_canon.py --only <draft>` first so the reviewer's time goes to what the linter cannot check. If no separate context is available, label the review as self-review. Shared rules for all agents: [docs/authority-and-scope.md](docs/authority-and-scope.md); power-directed questions: [docs/success-contract.md](docs/success-contract.md).

## Canonical read order

1. `book-agent/revision/master_storyline.md` — **single continuous story synopsis**, with all currently approved narrative changes already embodied, and **[OPEN]** markers for unresolved decisions. Its prose must read as what happens, not as an edit memo.
2. `book-agent/revision/change_requests.json` — source of truth for explicit authorial approvals and remaining decisions.
3. `book-agent/revision/historical_background.md` — factual context, dated historical anchors, divergences, historical/legal uncertainties and source URLs.
4. `book-agent/revision/war_base_assumptions.md` — demographic, treasury and military scenario assumptions to audit, not assert as fact.
5. `book-agent/revision/sources/rise_to_power.md` — original author-provided early-history proposal; preserve verbatim as an archival source.
6. `book-agent/revision/character_bible.md` — **authoritative character arcs and differentiated voice guidance** for the second draft.
7. `book-agent/revision/character_registry.json` — stable character IDs and documented relationships, including unresolved genealogy.
8. `book-agent/revision/legacy_character_crosswalk.json` — maps all 250 original character sketches to confirmed/provisional identities or retained secondary profiles.
9. `book-agent/revision/approved_change_index.md` — **generated** change-list and chronology, not story prose.
10. `book-agent/manuscript_chaptered.md`, `book-agent/beats.json`, `book-agent/character_bible.json`, `book-agent/bible.md`, `book-agent/concept.txt` — first-draft sources, potentially superseded by approved canon.

## Mandatory on author approval

- Revise the **actual narrative prose** in `master_storyline.md`, including knock-on effects across later sections, **before** calling it integrated. Never merely write a new entry saying the old material will be changed. Don't fill unresolved decisions with unsupported inventions.
- Update the structured CR or add a stable new CR ID in `change_requests.json`.
- If adding a CR, add its stable ID in a hidden coverage comment in the synopsis adjacent to the relevant plot section; the checker confirms IDs, not literary quality.
- Keep historical research, bibliographies and reasons for proposed divergences in `historical_background.md`, not explanatory comparisons in the storyline.
- **Fact changes.** Every CR draft has a `## Fact changes` section: a ```json list of the dates, ages, identities or linter-tracked plot facts it changes, including retirements (format in `book-agent/revision/cr_facts.py`), or the word "none". While drafting, run `python3 book-agent/revision/cr_facts.py preview <draft.md>`: it lists every passage in current canon that would still state the old value — that list is the start of the impact notes. On approval, copy the same list, plus the fact changes of each canon tension the author decided in favour of amending canon, into the CR's register entry as `"facts"`, run `python3 book-agent/revision/cr_facts.py apply CR-0xx` (updates `canon_facts.toml`; refuses unapproved CRs and stale values), revise every listed passage until `lint_canon.py` is clean. CI runs `cr_facts.py check` so the register and facts file cannot drift. Never edit `canon_facts.toml` by hand for an approved change; a clean lint checks only the facts in that file.
- **Canon tensions.** Every CR draft also has a `## Canon tensions` section: wherever the strongest version of the change conflicts with existing canon, both cases (the draft adapted to canon; canon amended, with its fact changes in a ```json block under that tension) and a recommendation, or the word "none". Tension blocks stay out of `## Fact changes` until the author decides; `cr_facts.py preview --tensions <draft.md>` previews each one on top of the fact changes. A plot fact protected by a linter pattern is amended with `retire_forbidden`. Canon is revisable ([R8](docs/authority-and-scope.md)); the author decides each tension.
- Run `python3 book-agent/revision/sync_master_storyline.py --write`, then `--check`; commit all three related files when applicable. The push-triggered workflow updates the generated `approved_change_index.md`. The PR workflow rejects stale administrative synchronization.
- If the change creates, renews, changes or ends a treaty, lease, loan, guarantee, charter or life office, update `commitments/data/ledger.toml` and run `python3 commitments/ledger.py check`; CI fails when a ledger quote no longer matches the storyline.
- Never claim that generated index synchronization guarantees literary integration. It does not. Review the narrative in light of the author’s approval.
- Preserve `main`, old manuscripts, original beat and character sources until the author authorizes an actual prose revision; use review branches and PRs.
- Do not mistake an editorial proposal, assistant suggestion or historical illustration for author-approved canon.

When presenting the story, link only to `master_storyline.md`. For source claims use the historical background document.

## Protected intent
